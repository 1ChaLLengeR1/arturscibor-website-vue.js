# Sekcja Projekty — plan

Status: **plan zaakceptowany, implementacja w toku** (patrz commit po tym pliku).

## Punkt wyjścia

- Warstwa `src/api/projects/`, `src/api/admin/projects/` i `src/storage/projects/` **już istnieje i jest kompletna** — ten sam stan co Work/Tools/Contact przed ich krokami UI. Gotowe akcje: `projects/apiGetProjectsCollection`, `apiGetProject`, `apiCreateProject`, `apiUpdateProject`, `apiDeleteProject`, `apiAttachProjectImage`, `apiDetachProjectImage`.
- Endpointy (z `docs/rest_api_docs.json`, zrzut ekranu):

  | Endpoint | Auth |
  |---|---|
  | `GET /api/v1/projects/collection` | brak |
  | `GET /api/v1/projects/{project_id}` | brak |
  | `POST /api/v1/admin/projects/create` | JWT |
  | `PUT /api/v1/admin/projects/{project_id}/update` | JWT |
  | `DELETE /api/v1/admin/projects/{project_id}/delete` | JWT |
  | `POST /api/v1/admin/projects/{project_id}/images` | JWT |
  | `DELETE /api/v1/admin/projects/{project_id}/images/{file_id}` | JWT |

- **Obecne `Projects.vue`, `SingleProject.vue`, `AdminProjects.vue` (+ `AddProject.vue`, `ListProjects.vue`, `EditProject.vue`) są martwe** — `admin/loadProjects`/`admin/loadProject` nie istnieją w store. `SingleProject.vue` jest dodatkowo realnie zepsute w JS (`return { ..., loadProject }` odwołuje się do niezdefiniowanej zmiennej — wywalałoby się na starcie). Stary model miał podział zdjęć na „frontend”/„backend” i osobny plik do pobrania — nowe API tego nie ma (jeden gallery `images[]`, bez kategorii, bez pliku do pobrania).
- Kształt danych (`ProjectResponseData`): `name` to zwykły string (nie `MultiLangText`, w przeciwieństwie do `Work`/`Tools`), `short_description`/`description` są `MultiLangText`, `level` to enum (`beginner/intermediate/advanced/expert` — ten sam kształt co skala umiejętności w Tools), `technologies` to `string[]`, `github_url`/`live_url` to dwa osobne linki, `completed_at` to pojedyncza data, `images[]` to galeria (z `sort_order`, bez endpointu do zmiany kolejności).

## Ustalenia

1. **Zachowuję istniejący routing** `/projects` (grid) + `/projects/project/:id` (szczegóły) — w przeciwieństwie do Tools (modal), tu ma to sens: to realna podstrona z własnym URL-em, case study projektu, coś co warto móc zlinkować bezpośrednio.
2. **Kafelek na `Projects.vue`**: obrazek (pierwszy z galerii), nazwa, `level` jako badge, `short_description` (przycięty), kilka pierwszych `technologies` jako chipy, link do `/projects/project/:id`.
3. **`SingleProject.vue`**: pełny `description` przez `MarkdownRenderer` (jak w Work/Tools), galeria zdjęć (karuzela — `v-carousel`, jest już w projekcie z Vuetify), `technologies` jako chipy, `level`, `completed_at`, przyciski `github_url`/`live_url` (oba opcjonalne, pokazywane gdy są).
4. **Panel admina**: wzorzec Add/List/Edit jak w Work/Tools. `level` jako select z tymi samymi etykietami co skala umiejętności w Tools (`beginner/intermediate/advanced/expert`), ale osobny namespace i18n (`projects.level.*`) — inna domena, inne słowa pasują („Projekt na poziomie zaawansowanym” a nie „Zaawansowana znajomość”).
5. **Confirm-delete** — dokładnie ten sam mechanizm co w Work/Tools/AboutMe/Contact (`requestConfirm`) na: usuń projekt (z ostrzeżeniem o kasowaniu zdjęć — cascade), usuń pojedyncze zdjęcie z galerii.
6. **i18n od razu** — `projects.*` (public) + `admin.projects.*` (admin), tak jak w Tools/Contact.
