# Sekcja Work — warstwa UI (public + admin)

Status: **plan do akceptacji, implementacja jeszcze nie ruszona**.

## Punkt wyjścia

- Warstwa `src/api/work/`, `src/api/admin/work/` i `src/storage/work/` (state/getters/mutations/actions) **już istnieje i jest kompletna** — powstała przy okazji [[1.home-section.md]]/kroku 1, choć dotyczy innej domeny niż tam opisana. Wszystkie 9 endpointów z `docs/rest_api_docs.json` (public `GET /work/collection` + 8 adminowych) mają już gotowe akcje Vuex (`work/apiGetWorkCollection`, `apiCreateWork`, `apiUpdateWork`, `apiDeleteWork`, `apiAttachWorkLogo`, `apiRemoveWorkLogo`, `apiCreateWorkItem`, `apiUpdateWorkItem`, `apiDeleteWorkItem`). Zweryfikowano też, że backend faktycznie odpowiada zgodnie z kontraktem (`GET /work/collection` → `200 {status:"SUCCESS", data:[]}`, `POST /admin/file/init` bez JWT → `401`).
- **Brakuje wyłącznie warstwy `.vue`**: `Work.vue` to dziś pusty tytuł, a panelu `Admin/Work` w ogóle nie ma (ani widoku, ani wpisu w nawigacji). To jest zakres tego kroku.
- Jedyna rzecz, której w Vuex/API brakuje: `work/apiAttachWorkLogo` przyjmuje gotowe `{file_id}` — nie ma (analogicznie do `aboutme`/`cv`) akcji ogarniającej cały handshake uploadu logo (`init → upload bytes → confirm → attach`). Trzeba ją dopisać.

## Ustalenia

### 1. Reużywalny handshake uploadu plików (Vuex)

Wzorzec `init → uploadFileBytes → confirm → <domain attach>` jest dziś **zduplikowany 1:1** w `aboutme/apiUploadAboutMeImage` i `cv/apiUploadCv` (`src/storage/aboutme/actions.ts:54`, `src/storage/cv/actions.ts`) — różni się tylko `directory`/`file_type` i wywołaniem domenowym na końcu. Dodanie trzeciego niemal identycznego bloku dla loga firmy w `work` to sygnał do wydzielenia.

**Decyzja:** dodać `src/storage/common/fileUpload.ts` z jedną funkcją:

```ts
export async function uploadFileHandshake(
  commit: Commit,
  file: File,
  params: { directory: string; file_type: FileType }
): Promise<string | null> // zwraca file_id albo null (i sama notifyError w środku)
```

`apiUploadAboutMeImage`, `apiUploadCv` i nowe `work/apiUploadWorkLogo` wołają tę funkcję, dostają `file_id` i robią już tylko swój krok domenowy (`attachAboutMeImage`, `uploadCv`, `attachWorkLogo`). To realny refaktor istniejących plików, nie tylko nowy kod dla `work` — zgłaszam do akceptacji, bo dotyka `aboutme`/`cv`, które nie są w zakresie „work”.

### 2. Reużywalny komponent `UploadFile.vue`

Analogicznie po stronie `.vue`: `AboutMeForm.vue` ma już dziś **dwa** identyczne bloki (`v-file-input` + `v-btn :disabled="x.length!==1"` + reset po wysyłce) — dla zdjęcia i dla CV. Panel `Admin/Work` potrzebuje trzeciego (logo firmy). To uzasadnia wydzielenie.

**Decyzja:** nowy `src/components/util/UploadFile.vue` — komponent prezentacyjny, bez wiedzy o Vuex:
- props: `label: string`, `accept?: string`, `buttonLabel?: string`
- emit: `@upload="(file: File) => void"` — tylko gdy wybrano dokładnie 1 plik; komponent czyści swój `v-model` po emisji
- rodzic sam decyduje, co zrobić z plikiem (`store.dispatch("work/apiUploadWorkLogo", { workId, file })`, `store.dispatch("aboutme/apiUploadAboutMeImage", file)`, itd.) — komponent nie zna nazw akcji, więc nadaje się do wszystkich trzech miejsc bez dodatkowej konfiguracji.

Miejsca podmiany: `AboutMeForm.vue` (2×, zdjęcie + CV) + nowy upload loga w `AdminWork`. Podmiana w `AboutMeForm.vue` wchodzi w zakres tego kroku (bo bez niej nie ma z czym porównać/uzasadnić wydzielenia), ale bez zmiany zachowania — czysty refaktor UI.

**Do wyrzucenia:** `src/components/Home_Admin/UploadFile.vue` — martwy kod sprzed refaktoru (stary wzorzec `fetchData`/`JS/Notification`, zero importów w repo — sprawdzone `grep`). Koliduje nazwą z nowym komponentem, więc kasujemy przy okazji.

### 3. Public `Work.vue`

Wzorzec z `Home.vue`: dispatch `work/apiGetWorkCollection(locale.value)` w `setup()`, dane z gettera `work/collection`, render listy firm (`WorkResponseData[]`) z ich `items`. Bez watchera na zmianę `locale` po zamontowaniu — `Home.vue` też tego nie robi, więc zostajemy spójni z istniejącym (niedoskonałym) wzorcem zamiast wprowadzać nowe zachowanie w tym kroku.

Struktura komponentów po wzorze `AdminProjects` (`View` = kontener + podkomponenty w `src/components/<Domain>/`):
- `src/components/Work/CompanyCard.vue` — jedna firma: logo, nazwa, lista `items` (stanowisko, zakres dat, `employment_type`, `body_markdown` jako markdown przez istniejący `MarkdownRenderer.vue`, `skills`)
- `Work.vue` iteruje po `collection` i renderuje `CompanyCard` dla każdej firmy

### 4. Admin `Work`

Nowa domena w panelu admina, osobna od `AdminHome` (który dziś = tylko `AboutMeForm`) — po wzorze `AdminProjects`/`AdminContact`, nie jako dopisek do Home.

- `src/views/admin/AdminWork.vue` — kontener, analogicznie do `AdminProjects.vue`
- `src/components/AdminWork/AddCompany.vue` — formularz `company_name` + `numeric` → `work/apiCreateWork`
- `src/components/AdminWork/ListCompanies.vue` — lista firm z akcjami (edytuj / usuń / zarządzaj logo i stanowiskami)
- `src/components/AdminWork/EditCompany.vue` — edycja `company_name`/`numeric` (`apiUpdateWork`), upload/usunięcie logo przez `UploadFile.vue` + `apiUploadWorkLogo`/`apiRemoveWorkLogo`, oraz CRUD `items` (`apiCreateWorkItem`/`apiUpdateWorkItem`/`apiDeleteWorkItem`) — `WorkItemCreatePayload.title` wymaga `MultiLangText` (`{pl, en}` na raz przy tworzeniu), a `WorkItemUpdatePayload` edytuje pojedynczy język przez `language_code` (domyślnie `"pl"`) — czyli ten sam wzorzec przełącznika PL/EN co w `AboutMeForm.vue`
- Routing: nowy wpis `{ name: "adminwork", path: "/adminwork", component: AdminWork, meta: { auth: true } }` w `src/router/index.js`, plus wpis w `src/components/JS/ArrayLinksAdmin.ts` (`labelKey: "nav.adminWork"`, `link_name: "adminwork"`) — nowy klucz i18n `nav.adminWork`, analogicznie do istniejących `nav.admin*`.

### 5. i18n

Publiczny `work.title` już istnieje (`Doświadczenie`/`Experience`). Do dopisania w `pl.json`/`en.json`: etykiety `employment_type` (6 wartości enuma: `full_time, part_time, contract, b2b, internship, volunteer`) potrzebne do czytelnego wyświetlenia na `Work.vue` i w formularzu admina, oraz `nav.adminWork`.
