# Sekcja Narzędzia (Tools) — plan

Status: **plan do akceptacji, implementacja jeszcze nie ruszona**.

## Punkt wyjścia

- Warstwa `src/api/tools/`, `src/api/admin/tools/` i `src/storage/tools/` (state/getters/mutations/actions) **już istnieje i jest kompletna** — dokładnie ten sam stan, w jakim był `work` przed [[2.work-section.md]]. Wszystkie akcje Vuex są gotowe: `tools/apiGetToolsCollection`, `apiCreateTool`, `apiUpdateTool`, `apiDeleteTool`, `apiAttachToolImage`, `apiDetachToolImage`.
- Endpointy z `docs/rest_api_docs.json` (ekran z obrazka):

  | Endpoint | Auth |
  |---|---|
  | `GET /api/v1/tools/collection` | brak (public) |
  | `POST /api/v1/admin/tools/create` | JWT |
  | `PUT /api/v1/admin/tools/{tool_id}/update` | JWT |
  | `DELETE /api/v1/admin/tools/{tool_id}/delete` | JWT |
  | `POST /api/v1/admin/tools/{tool_id}/images` (dopięcie potwierdzonego pliku) | JWT |
  | `DELETE /api/v1/admin/tools/{tool_id}/images/{file_id}` | JWT |

- **Brakuje**: jednej akcji store (`tools/apiUploadToolImage` — handshake uploadu, analogicznie do `work/apiUploadWorkLogo`) oraz **całej warstwy `.vue`**.
- **Ważne odkrycie:** obecne `src/views/Tools.vue` i `src/views/admin/AdminTools.vue` (+ komponenty `AddItem.vue`, `DeleteModificationItem.vue`, `itemLi.vue` w `src/components/AdminTools/`) są dziś **martwe / wywalają się w runtime** — odwołują się do modułu Vuex `admin/...` (`admin/loadTools`, `admin/loadProjects`...), który już nie istnieje w drzewie store (`src/storage/index.ts` rejestruje: `util, auth, work, aboutme, cv, tools, projects, contact` — nie ma `admin`). Publiczna `/tools` dziś realnie się crashuje (`store.getters['admin/loadTools']` to `undefined`, wywołanie `.sort()` na nim rzuca błąd). To dokładnie ten sam punkt startowy, w jakim był `Work.vue` przed poprzednim krokiem — tylko że tu strona nie jest pusta, tylko zepsuta.

## Ustalenia

1. **Layout kafelków** — obecny (martwy) `Tools.vue` ma już dokładnie ten model UI, o który prosisz: grid kart (ikona, nazwa, opis, poziom umiejętności, przycisk „więcej"). Nowa wersja **zachowuje ten layout i CSS**, tylko podłącza go pod nowy `tools` store + i18n zamiast zepsutego `admin/loadTools`. Nie projektuję nowego wyglądu od zera.
2. **Sortowanie**: po `numeric` rosnąco (tak jak w martwym kodzie dziś). W przeciwieństwie do Work, Tools nie mają osi czasu (brak dat) — `numeric` (ręczna kolejność ustawiana w adminie) to jedyny sensowny klucz sortowania.
3. **Upload obrazka narzędzia**: nowa akcja `tools/apiUploadToolImage({ toolId, file })` przez już istniejący wspólny `uploadFileHandshake` (`directory: "tools"`, `file_type: "photo"`) + `attachToolImage` — to już **czwarte** użycie tego mechanizmu (po aboutme, cv, work), więc żadnych nowych abstrakcji, czysty reużyty helper.
4. **Panel Admin/Tools**: pełny rebuild na wzór `AdminWork` (`AddTool` / `ListTools` / `EditTool`) w miejsce martwych `AddItem.vue` / `DeleteModificationItem.vue` / `itemLi.vue`, które kasujemy. Route `admintools` i wpis w nawigacji (`nav.adminTools`) **już istnieją** — nic nowego w routerze/nawigacji nie trzeba dodawać (w przeciwieństwie do Work, gdzie robiliśmy to od zera).
5. **i18n od razu** — w przeciwieństwie do Work (gdzie i18n admina dorabialiśmy w osobnym kroku), tu robimy `t()` w obu miejscach (public `tools.*` i admin `admin.tools.*`) już przy pierwszym podejściu, żeby nie wracać drugi raz.

## Decyzje (potwierdzone)

1. **Obrazki**: jeden obrazek = ikona kafelka. Upload w adminie **zastępuje** dotychczasowy obrazek (jak logo firmy w Work), bez galerii wielu zdjęć — mimo że `ToolResponseData.images` to technicznie tablica z `sort_order`, używamy tylko pierwszego elementu (`images[0]`). Analogiczne akcje: `apiUploadToolImage` (upload + attach) i `apiDetachToolImage` (usunięcie), oba operujące na jedynym obrazku.
2. **Pasek postępu**: `v-progress-linear` (Vuetify) zamiast gołej liczby — poziom umiejętności 0–100 renderowany wizualnie.
3. **Opis (`information`)**: przez `MarkdownRenderer.vue` (ten sam komponent co w opisach stanowisk w Work) — pozwala na formatowanie (listy, pogrubienia) zamiast czystego tekstu.
